# 发射 NFT 与子币发射

Type: grilling
Status: claimed
Blocked by: 01, 05

## Question

定义治理激励铸造量达到“剩余未铸造量百分比”后获得发射额度的公式、额度消耗和并发边界；`LOVE20LaunchNFT` 的铸造、转让、永久锁定到子币合约、发射关系记录和不可重复使用规则；去中心化发射与中心化发射的授权差异；其他链已发射子币作为保留代币但不可触发发射的识别规则。

## Comments

用户补充确认：BSC 版公平发射由 `LOVE20LaunchNFT` 持有者执行；发射时可指定首次分配的接收钱包或合约，由接收方自行二次分配。父币托底池以及底层核心中的父币申购逻辑不再存在；父币申购作为 `launch` 代码库中多种公平发射初始分配机制之一实现。

用户确认：发射额度按 `tokenAddress + memberId` 累计实际治理激励铸造量；达到当前剩余未铸造量乘以配置比例（`1e18` 精度）时，消耗一份额度并获得一枚 `LaunchNFT`，超出部分保留，额度随 NFT 转移。

用户补充确认：治理激励铸造与当期达到额度的 `LaunchNFT` 铸造在同一笔交易内原子完成，不提供额外的独立铸造调用。`Mint` 必须修复旧版可能重复铸造/重复销毁的状态判断，任何奖励和发射 NFT 结算只能成功一次，失败时全部回滚。

用户已确认：`LaunchNFT` 发射成功后不在 NFT 合约内执行真正销毁，而是转移到对应的子币合约作为永久锁定；发射合约记录子币与发射 NFT 的关系，已使用的 Token ID 不再重复，枚举查询包含这些已锁定 NFT。

用户确认：发射额度阈值中的“剩余未铸造量”按本次治理激励铸造前的 `maxSupply - totalSupply` 计算，不扣除已预留但尚未领取的奖励。

用户确认：发射额度阈值比例在 `Launch` 初始化时作为全局参数设置，所有代币社区使用同一比例，部署后不可修改，比例使用 `1e18` 精度。
