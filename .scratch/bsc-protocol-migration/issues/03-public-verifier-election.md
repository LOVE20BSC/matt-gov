# 公共验证者竞选与验证

Type: grilling
Status: resolved
Blocked by: 01, 02

## Question

定义每轮公共验证者候选资格、申请说明和分成比例；撤销/修改申请时清空已有投票的精确定义；治理投票排名与验证开始区块的映射；首个提交者如何锁定本轮行动验证资格；验证如何分批提交、重复提交和失败处理；治理者如何监督实际验证者，以及验证激励如何铸造和结算。

## Answer

- **候选资格与资料**：候选人必须是目标代币社区中拥有有效治理权的 `MemberNFT`，以 `memberId` 记录；不要求 SL/ST 或额外押金。申请说明和分成比例属于链群行动执行合约数据，比例统一使用 `1e18` 精度。
- **申请与冻结**：投票阶段内可新增、撤销或修改申请；每次申请拥有独立 `applicationId`，并按 `tokenAddress + actionId + ActionRound` 作用域记录。撤销/修改将该 `MemberNFT` 当前关联的 `applicationId` 置为 `0`，从当前排名列表移除，不扫描完整列表、不自动补位，也不删除旧申请或其票数；重新申请或修改完成后创建新的 `applicationId`，新申请从零计票，只有收到新投票后才重新参与排名，旧申请数据仅供历史查询且不参与当前排名。投票阶段结束后，本轮候选、排名和分成比例冻结，之后的变更只影响下一轮。
- **候选列表与排名**：完整申请记录保留在可分页查询的列表中，供前端展示当前及历史状态；合约内部只维护容量为前 `n + 1` 名的排名列表，`n` 为验证阶段分割线数量，并保存 `applicationId -> rankIndex` 以避免查找。排名只考虑各 `MemberNFT` 当前关联且非零的 `applicationId` 及其票数，先按累计票数降序、再按 `applicationId` 升序排序。申请失效时只移除该申请，并只整理排名列表中已有的其他申请；不扫描完整列表、不从榜外申请自动补位。只有某候选人收到新投票时，才比较该候选人的当前申请和累计票数，符合前 `n + 1` 名才插入或替换排名。排名列表未满时可直接进入，已满时新候选必须严格超过当前末位，平票不替换。新申请必须重新获得投票才可能入榜，旧申请记录和票数不参与当前排名。没有任何有效申请进入排名时，排名列表为空，本轮没有公共验证者。完整列表不参与验证遍历，所有列表和排名状态均按 `tokenAddress + actionId + ActionRound` 隔离。
- **候选投票记账**：同一治理者同一轮可多次投票；标准回调提供投票人的 `memberId` 和本次治理票增量 `votes`，行动层 KV 由具体执行合约定义并指定候选人的 Member ID。前端根据执行合约要求编码，核心只透传。行动执行合约据此查找该候选人当前关联的 `applicationId`；关联为 `0` 时拒绝投票，关联有效时将本次全部 `votes` 增量记入该申请。随后只对该候选人执行增量排名：已入榜候选仅向前比较并交换，未入榜候选仅与当前末位比较，未达到前 `n + 1` 名时不修改排名列表，不为其他候选人自动补位。下一次投票可以指定其他候选人。核心 `Vote` 负责投票人本轮对行动的治理票总量上限，行动执行合约不维护投票人的治理票累计值；旧 `applicationId` 的票数保留但不再计入当前排名。
- **无候选人边界**：本轮没有有效候选申请或候选投票总量为零时，不产生公共验证者，任何主体都无权提交本轮验证；底层 Proposal 激励仍可由 Proposal Target 铸造，链群行动执行合约取得后可以按业务规则销毁该笔激励，但不得进行行动层分配，链群行动者、链群服务、公共验证者和链群 owner 的行动层激励全部为 `0`。
- **验证开放时间**：初始化传入严格递增的验证阶段分割线数组；第 1 名在验证阶段开始时可提交，数组有 `n` 个分割线时排名前 `n + 1` 名可提交。分割线满足 `0 < split < 1e18`，开放区块按验证阶段起始区块及阶段区块数计算；数组为空时仅第 1 名可提交。
- **验证集合与批次**：行动阶段结束时快照所有至少有一个参与成员的链群 `MemberNFT`（`groupId`），空链群不纳入；后续链群停用、恢复或新增不改变本轮集合。每个链群按快照成员历史顺序维护连续游标，`startIndex` 必须等于已验证数量，支持分批提交，禁止重复、跳过或乱序。
- **本轮锁定与授权**：首个有效批次永久锁定本轮公共验证者 `memberId`，不设置失效、接管或代理；之后批次只能由该 `memberId` 当前 `MemberNFT` 持有人提交。NFT 转移后由新持有人继续，锁定的身份不变。
- **已知失联取舍**：永久锁定且不设接管意味着锁定的公共验证者停止提交时，本轮行动层激励会保持为 `0`；这是为避免中途换人、重复验证和治理状态复杂化而确认的协议取舍。前端和运维验收必须把该结果视为可预期状态，不得把它误判为底层 Proposal 激励失败。
- **完成条件与激励**：公共验证者必须完成全部快照链群的验证才算成功。验证不完整时，仅链群行动执行合约可发起调用 `ActionTarget` 铸造底层 Proposal 激励；`ActionTarget` 以自身身份调用 `Mint` 后将激励转回该执行合约，执行合约可以销毁该笔激励，但链群行动、行动者、链群服务、公共验证者和链群 owner 的行动层分配全部为 `0`。完整时，先按该行动的行动激励权重取得链群服务激励预算，再由公共验证者按冻结比例 `r` 获得该行动预算的 `r`，余下按链群服务规则分配给链群 owner。
- **链群 owner 与监督**：链群 owner 是 `MemberNFT`（`groupId`）主体，不是钱包地址；不再保留群级验证 delegate 或代理验证者。治理者在投票阶段同时为行动和候选人投票，下一轮不给有问题的候选人投票完成监督，不回溯扣减历史激励。
- **底层回调边界**：Proposal 创建、推举和投票分别触发对应回调；`Vote` 传递 `proposalId`、本次投票对应的 `memberId`、治理票增量和逐提案不透明 KV，但不解析候选申请等行动业务；`targetMode = Callback` 且目标为合约时始终回调，空 KV 也传递空数组，回调失败回滚对应外层交易。候选竞选、快照、批量验证和服务激励均由链群行动/服务行动执行合约处理。
