# 规格文档撰写指南

目标：用最少的文字，让实现者和测试者得到同一个、可验证的行为。精简表达，不精简约束。

## 文档分工

- `README.md`：范围、阅读入口，不复制各模块规则。
- 模块规格：当前行为、接口、状态和边界；一条规则只在负责它的模块定义，其他文件直接链接。
- `08-testing.md`：场景及预期结果，不另定义协议；跨仓库证据要求见组织验收文档。
- `overview.md`：非规范概览，不另写公式、参数默认值或权限例外。
- `CHANGES-*`、`.scratch`：迁移差异和决策来源，不代替当前规格。

文件归属、迁移位置和单一来源规则见 [规格文档结构](specification-structure.md)。按现有模块拆分，不为了行数再拆文件，也不为统一模板增加空章节。

## 最小内容

按业务阅读顺序组织，通常是“职责与依赖 → 状态 → 操作与公式 → 边界 → 验收链接”。只使用需要的章节。

| 内容 | 必须说清楚 |
| --- | --- |
| 状态 | 键、值、单位、初始值；当前值还是历史值；谁更新、何时冻结 |
| 写操作 | 调用者、前置条件、更新顺序、资产去向、返回值、事件、失败原子性、重复调用 |
| 读操作 | 查询范围、时间基准；不存在、零值、空集合、越界和分页行为 |
| 公式 | 每个变量来源、精度、运算顺序、舍入、零分母、溢出和剩余额度 |
| 外部调用 | 允许的调用方、参数透传或解释方、失败回滚或容错的具体边界 |
| 验收 | 前置状态、操作、预期结果；未运行的场景不得称为测试通过 |

已确定的 ABI 用 `solidity` 代码块原样保留参数类型、顺序、可见性和返回值；仅有函数名或参数示意时明确标注，不能冒充完整 ABI。公式和伪代码用 `text`，不能省略改变结果的中间取整。

## 表达规则

1. 一句话表达一个条件或结果。例如：“本轮已准备时直接返回，不更新三个累计账本。”
2. 命令用编号列表，字段或组合用表格，短约束用项目列表；不重复用三种形式描述同一件事。
3. 保留“必须、仅、不得、可以”的差别。示例值不是默认值，可选能力不是必需能力。
4. 用准确的 `memberId`、`tokenAddress`、`proposalId`、`round` 等名称。不得为缩短文字混淆身份、单位或作用域。
5. 不重复“本文档定义”“关键设计”“新旧对比”。理由只保留能防止误实现的一句；详细讨论链接到来源。
6. 不保存手工行数、预估行数、固定阅读时长和重复目录。链接使用真实相对路径，优先章节锚点，不引用易变化的“第 X 节”。
7. 标准能力可引用已确定的标准或本地接口；自有规则不能只写“沿用旧版”。未核对的旧路径标为待核对，不能编造提交或宣称已验证。
8. 旧代码文件统一写为 `LOVE20TKM/<仓库>/<路径>`；同一行有多个文件时，每个文件都写完整路径，不能省略仓库前缀。仅提及合约或函数名称时不必伪造文件路径。

## 示例

示例只在公式、时序或边界容易误读时添加，一组短数据解释一个问题。标明整数单位；需要展示舍入时使用最小单位，禁止把整数公式算成近似小数。

例如：以代币最小单位计，`govReward = 5`、`proposalReward = 3`，且没有加速质押和达标 Proposal。本轮准备使 `rewardReserved` 增加 `8`，`rewardBurned` 增加 `3 + 3 = 6`，未结算额度增加 `2`；再次准备不改变账本。

不再用多个名字、钱包、轮次重复演示同一结果。不能用示例增加正文未定义的权限或经济规则。

## 冲突与缺口

- 结构整理不授权修改协议。冲突在所属模块的“待确认”节列出双方规则、来源和受影响操作；不得通过删掉一方假装解决。
- 已确认的用户决策同步到所属规格和验收；旧票据保留为历史，不回写成新的讨论。
- 未定义的 ABI、默认值、异常路径保留为具体缺口，不擅自补一个“合理”的值。
- 只有影响实施的条目使用“待确认”；不要把语言润色包装成新的设计议题。

## 交付前消融

- 删除后，是否仍能确定权限、公式、状态转换、失败条件和验收结果？能则删；不能则保留或链接到唯一来源。
- 对照修改前检查：接口、字段、公式、单位、边界、例外、事件和验收场景是否逐项保留。
- 重算示例，检查链接、章节引用和 `git diff --check`；文本搜索只能辅助，不能证明语义等价。
- 明确区分“文档整理完成”和“协议已通过审查”。审查方法见 [审查指南](review-guide.md)。
