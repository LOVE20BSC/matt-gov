# Issue tracker

本仓库使用本地 Markdown 维护 Issue、规格和 Wayfinder 决策票据。

## 文件约定

- 每个工作项使用一个目录：`.scratch/<feature>/`
- 地图文件：`.scratch/<feature>/map.md`
- 子票据：`.scratch/<feature>/issues/NN-<slug>.md`，从 `01` 开始编号
- 票据顶部使用 `Type:` 和 `Status:`；Wayfinder 状态为 `open`、`claimed` 或 `resolved`
- 讨论记录追加在 `## Comments` 下，结论追加在 `## Answer` 下

## Wayfinder 操作

- 地图是低分辨率索引，不重复保存子票据的完整答案。
- 子票据用 `Blocked by: NN, NN` 表示依赖；所有依赖 resolved 后才进入 frontier。
- 认领票据前先把 `Status` 改为 `claimed` 并提交，避免并行重复处理。
- 解决票据时追加答案、改为 `resolved`，再把结论链接追加到地图的 `Decisions so far`。
- 不明确到可以写成问题的内容留在地图 `Not yet specified`，不要提前拆成票据。

## Triage

每个 triage 项目使用一个类别标签和一个状态标签。由 AI 在 triage 中产生的评论或 Issue 必须以以下声明开头：

> *This was generated by AI during triage.*
