# P-07 · 回调 × 可达写入口 × 中间态

**路径**：`Submit:326-338` → `Vote:281-287` → `Launch:149-151`

**固定三问**：状态修改顺序有无可利用窗口 / 攻击者能在哪个时点插入什么 / 结论落在哪个不变量。

## 每个回调能看见的中间态

| 回调 | 已写入 | 尚未写入 |
| --- | --- | --- |
| `onProposalCreated` | `_proposals`、`_proposalIdsByAuthor`、`_submits[round]`、`_submitInfoByProposalId`、`_submitInfoBySubmitterId`、`ProposalSubmitted` 事件、可能已 `sync` | `ProposalCreated` 的**接收方**副作用（如果有） |
| `onProposalSubmitted` | 同上（在 `:117` 才调） | — |
| `onProposalVoted` | `_totalVoteAmountByRound`、`_voteAmountByProposalId`、`_voteAmountByMemberId`、`_voteAmountByMemberIdByProposalId`、三个名册、`_voterBoostByMemberId`、`_totalVoterBoostByRound`、`VoteCast` 事件 | — |
| `onTokenLaunched` | `_tokens`、`_parentTokenByTokenAddress`、`_tokenAddressBySymbol`、`_childTokens`、`remaining` 已扣、`TokenLaunched` 事件 | — |

**四个面都是「先写后调」，没有半写状态。** 这一点由 `Submit:301-307 < :326`、`Vote:256-267 < :286`、`Launch:133-147 < :150` 三处行序保证。

## 能否伤害第三方

| 途径 | 能否 | 原因 |
| --- | --- | --- |
| 恶意 target 让**别人**的提交失败 | 不能 | target 由**提案作者**在 `ProposalBody.target` 指定；别人的提交走自己的 target |
| 恶意 target 让**别人**的投票失败 | 不能 | 同上；只有给这条提案投票的人会进这个 target，而他们知道 target 是谁 |
| gas 炸弹阻断票权记录 | 局部 | 只阻断「给这条提案投票」，且整批 `vote` 会回滚，投票人可拆批重试 |
| 回调内读别人的票权并据此行动 | 可以，但无收益 | 读到的都是公开状态 |
| 回调内改别人的状态 | 不能 | 所有写入口都有 `onlyMemberOwner(memberId)` 或 `onlyMint`/`onlyProposalTarget` |

## 结论落在哪个不变量

> **回调可见的状态必须是「已完成」的，且回调不能改变别人的状态。**

两条都成立：

1. 三处写入顺序都是「写 → 发事件 → 回调」；
2. 四个回调面的 13 个写入口里，只有 3 个（`vote`/`submitNewProposal`/`launchToken`）接受「自己的 memberId」，其余全部要求 NFT 归属或合约身份。

## 判定

| 项 | 结论 |
| --- | --- |
| 回调内重入写入口 | **可达，但都在自己的状态上** |
| 回调内达到半写状态 | **不可达** |
| 用回调阻断第三方 | **不可达** |
| 回调内抬高票权后再投票 | **允许且无超发**。`Vote:77` 每次重读 `voteLimit`，`Vote:250-254` 用同一个上限做累计校验 |
| `D-09` 的「core 不传 `msg.sender`」 | **不构成风险**。`Mint.onlyProposalTarget` 用 `Submit.proposalTarget` 反查，不依赖 target 自报身份 |

**一句话**：回调面的安全性不来自「加锁」，而来自「作者自选 target + 先写后调 + 所有写入口按 NFT 归属鉴权」这三条同时成立。
